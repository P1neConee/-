## 0. 内容体系速览

本站（全能知识库型）把内容分成四类，正文都是 Markdown，区别在于「放哪 + 是否登记」：

| 类型 | profile | 正文位置 | 登记文件 | 一句话用途 |
| --- | --- | --- | --- | --- |
| 博客文章 | post | `source/_posts/` | 无 | 随时间发布的一次记录 |
| 专栏 Topic | topic | `source/_posts/`（文章声明归属） | `source/_data/topic/<id>.yml` | 按顺序阅读的系列文章 |
| 知识库 Wiki | wiki | `source/wiki/<id>/` | `_data/wiki.yml` + `_data/wiki/<id>.yml` | 有目录树、可反复查询的指南 |
| 笔记本 Notebook | notebook | `source/notebooks/<id>/` | `_data/notebooks/<id>.yml` | 短笔记 + 层级标签 |

写什么内容用哪份模板：见 [文章模板/00-使用说明.md](文章模板/00-使用说明.md) 的对照表；本手册负责「为什么这样配」与「配置参考」。

## 1. 目录结构与文件职责

```
stellar-knowledge/
├─ _config.yml              # Hexo 全局：标题/语言/时区/分页/permalink
├─ _config.stellar.yml      # Stellar 主题：外观/导航/侧栏/搜索/功能（本手册第 2.2 节）
├─ package.json             # 脚本：doctor / clean / build / server
├─ source/                  # 站点内容（唯一会被发布的部分）
│  ├─ _data/                # 集合登记数据（wiki/topic/notebooks + widgets 等）
│  │  ├─ wiki.yml           # Wiki 书架（决定哪些项目上架列表）
│  │  ├─ wiki/<id>.yml      # 单个 Wiki 项目描述
│  │  ├─ topic/<id>.yml     # 单个专栏描述
│  │  ├─ notebooks/<id>.yml # 单本笔记本描述
│  │  └─ widgets.yml        # （可选）自定义 Widget 实例
│  ├─ _posts/*.md           # 博客文章 / 专栏成员文章
│  ├─ wiki/<id>/*.md        # Wiki 文档页面
│  ├─ notebooks/<id>/*.md   # 笔记本笔记
│  └─ assets/               # 图片等资源（/assets/xxx.webp 引用）
├─ 文章模板/                # 写作模板库（不会被 Hexo 发布）
└─ public/                  # hexo generate 产物（部署目录）
```

**核心规则：**
- `source/` 之外的一切都不会发布 → 模板、手册、备份放根目录很安全。
- **文件名决定网址**：文章 `/posts/<文件名>/`，Wiki `/wiki/<项目ID>/<文件名>/`；Front Matter 的 `title` 只是显示标题。发布后不要改名。
- 数组配置（菜单、widgets）在主题配置里是**整体替换**；对象配置按层合并；`[]` 表示清空，`null` 视位置表示隐藏或继承。

## 2. 站点配置

### 2.1 `_config.yml`（Hexo 基础，本站当前值注释版）

```yaml
# Hexo 基础配置（节选，均带注释）
title: P1neConeeのblog        # 站点标题：侧栏/顶栏/HTML <title>
subtitle: 使用 Stellar 构建的真实场景   # 副标题（可被主题覆盖，见 2.2 brand）
author: 思远                  # 作者（默认作者）
language: zh-CN              # 语言（决定 i18n 文案与日期格式）
timezone: Asia/Shanghai      # 时区
url: http://localhost:4000   # 站点地址（发布时改成真实域名）
root: /                      # 站点的根路径（子目录部署时改）
source_dir: source           # 内容目录
public_dir: public           # 产物目录
new_post_name: :title.md     # hexo new 的文章命名
default_layout: post
permalink: posts/:title/     # 文章固定链接格式（:title = 文件名 slug）
date_format: YYYY-MM-DD
updated_option: date         # 没写 updated 时沿用 date（而不是文件 mtime）
per_page: 10                 # 归档/分类等默认每页条数
index_generator:             # 首页博客列表生成器
  path: ''
  per_page: 5                # 首页每页 5 篇
  order_by: -date
archive_dir: archives        # /archives/
category_dir: categories     # /categories/
tag_dir: tags                # /tags/
theme: stellar               # 启用的主题（必须与 node_modules 主题名一致）
```

> Hexo 自定义字段（`highlight`、`deploy` 等）与 Stellar 无关，按需配置；Stellar 主题配置**不读取** `_config.yml` 里的同名主题字段。

### 2.2 `_config.stellar.yml`（主题配置总览 + 本站完整注释版）

主题默认值位于 `node_modules/hexo-theme-stellar/_config.yml`，本站文件只写覆盖项。顶层分区一览：

| 分区 | 管什么 |
| --- | --- |
| `topbar / leftbar / rightbar` | 三栏区域：开关、品牌、菜单、widgets |
| `footer` | 主内容区页脚正文与分栏 |
| `profiles.<页面类型>` | 每类页面的默认菜单高亮、左右栏 widgets、路由 |
| `article` | 文章排版、列表卡片、页脚许可/分享 |
| `notebook` | 笔记本列表排序、标签图标 |
| `settings` | /settings/ 页面关于信息 |
| `appearance` | 外观预设、配色、字体、圆角、背景 |
| `search` | 站内搜索（local / algolia） |
| `comments` | 评论服务（默认关闭） |
| `tags` | 标签插件默认行为（note 颜色、gallery 尺寸等） |
| `features` | 深浅色切换、懒加载、灯箱、公式、图表等开关 |
| `services` | 数据服务端点（评分、投票、GitHub 等） |
| `canonical / open_graph / structured_data / inject` | SEO 与可信注入 |

## 3. Front Matter 完整参考

Front Matter 是文件顶部 `---` 之间的 YAML。**本站主题会对字段做严格校验，写错/写旧字段会构建报错**（Doctor 会指出来源与修复方向）。

### 3.1 四类内容实际使用的字段（本站已验证 ✓）

**博客文章 / 专栏文章**（`source/_posts/`）：

```yaml
---
title: 标题
date: 2026-09-05 09:00          # 格式 YYYY-MM-DD HH:mm
description: 一句话摘要（卡片/SEO 用，建议必写）
categories:
  - 方法                         # 稳定领域：方法/工具/学习/思考/观察
tags:
  - 知识管理
# cover: /assets/xxx.webp        # 可选：列表卡片封面
# collection:                   # 仅专栏成员文章需要
#   profile: topic
#   id: system-thinking
# listing:                      # 可选：置顶（正整数，越大越靠前）
#   priority: 1
---
```

**Wiki 文档页**（`source/wiki/<id>/`）：归属由目录自动判定，通常只需三个字段：

```yaml
---
title: 页面标题
description: 一句话摘要
permalink: wiki/site-handbook/navigation/   # 必填，与目录树 key 一致
---
```

**笔记本笔记**（`source/notebooks/<id>/`）：

```yaml
---
title: 笔记标题
date: 2026-08-20 09:00
updated: 2026-09-01 21:00       # 可选：列表按 updated 倒序
description: 一句话
tags:                           # 斜杠 / 生成层级标签树
  - 阅读/方法
  - 工具/笔记法
collection:
  profile: notebook
  id: reading-notes
# listing: { priority: 1 }      # 可选：笔记置顶
---
```

### 3.2 字段速查表

| 字段 | 内容 | 说明 |
| --- | --- | --- |
| `title` | 全部 | 显示标题（不是网址） |
| `date` / `updated` | 全部 | 时间；排序、归档、笔记 recent 依据 |
| `description` | 全部 | 摘要，进入卡片与 SEO meta |
| `categories` | 文章 | YAML 列表，稳定领域入口 |
| `tags` | 全部 | 文章/笔记的关联标签；笔记里带 `/` 是层级标签 |
| `cover` | 文章/笔记/集合 | 列表卡片封面图 URL |
| `permalink` | Wiki 页 | 显式访问地址 |
| `collection` | 专栏文章/笔记 | `profile` + `id` 二选一必须成对且有效 |
| `listing.priority` | 文章/专栏文章/笔记 | 置顶（非负整数）；Wiki 页与普通独立页不支持 |
| `excerpt` 或正文 `<!-- more -->` | 全部 | 控制列表摘要；更优先用 description |

### 3.3 官方文档收录、但需先用 Doctor 验证的字段

以下字段官方文档（rc.2）列出，本站 alpha 主题**未必全支持**；想用时先写最小样例跑 `npm run doctor`，报错就按提示去掉或改写法：

- 排版：`article.style`（tech/story）、`article.paragraph_indent`、页级 `banner.image/headline/tagline`
- 页脚/评论覆盖：`footer.references`、`footer.license`、`footer.share`、`comments.enabled`
- 可见性：`visibility.listed` / `visibility.searchable`（隐藏列表≠禁止访问）
- 创作标注：`article.ai_label`（官方较新概念）
- 页面级 SEO/注入：`seo.open_graph`、`inject.head_end` 等

**旧版字段禁区**（v1 写法，写了必报错）：顶层 `widgets:`、`wiki:`、`navbar` 卡片式 `banner:` 等 v1 字段，一律不要照抄旧教程。

## 4. Collection 登记与导航

### 4.1 Wiki（两级登记）

`source/_data/wiki.yml` = 书架（数组，顺序即展示顺序）：

```yaml
- site-handbook
- knowledge-management
```

`source/_data/wiki/<id>.yml` = 单个项目（本站真实文件注释版）：

```yaml
name: Stellar 建站手册           # 项目短名（卡片底部、Brand）
headline: 从第一篇到全站发布      # 主标题
tagline: 内容、导航、外观与发布检查 # 副标题
description: 学习在 Stellar 站点中组织…… # 项目介绍（列表卡片）
tags:
  - 知识库                       # 用于 Wiki 间“相关项目”
  - 建站实践
audience: 独立博主与文档维护者
route:
  path: /wiki/site-handbook/     # 项目路由前缀
navigation:
  tree:                          # 侧栏目录树：分组 → 页面 key（文件名，无 .md）
    从这里开始:
      - index
    写作与格式:
      - writing-format
      - tag-plugins
    导航与发布:
      - navigation
      - publishing
```

规则：
- tree 顺序 = 侧栏顺序 = 「上一篇/下一篇」顺序；页面必须真实存在。
- 项目首页通常是 `index`；也可用 `navigation.tree` 首项自动判定。
- Wiki 首页还可配置 `hero`（enabled / background.image / effect 等）——**动效类型（ferrofluid/light-rays）属于较新版本**，本站 alpha 请以 Doctor 为准。

### 4.2 Topic（专栏）

`source/_data/topic/<id>.yml`（本站真实文件）：

```yaml
name: 系统化整理
headline: 从记录到结构
description: 一个示例专栏：对象、关系与边界如何落到每天的整理动作上。
route:
  start: system-01-boundary      # 系列入口文章（首篇文件名）
article:
  style: tech                    # 系列文章排版风格
```

- 成员文章在 `_posts/` 里通过 Front Matter `collection: {profile: topic, id: <id>}` 归属；
- 系列阅读顺序按 `date`（想固定顺序就把日期按阅读顺序排）；
- 可选总列表限定：`source/_data/topic.yml` 里写 `publish_list: [id1]`；不写 = 全部上架。
- 专栏页默认沿用站点品牌，卡片封面用独立 `cover`（与成员文章互不继承）。

### 4.3 Notebook（笔记本）

`source/_data/notebooks/<id>.yml`（目录名是复数 notebooks，本站真实文件）：

```yaml
name: 阅读笔记
headline: 摘录、方法与回访
description: 一本书、一篇文章留下一条能被再次使用的笔记。
route:
  path: /notebooks/reading-notes/
listing:
  order: 1                       # 笔记本集合的展示顺序
  per_page: 10                   # 0=不分页；null=继承站点分页
  sort: { field: updated, direction: desc }  # 笔记排序
```

- 笔记放 `source/notebooks/<id>/`，Front Matter 声明 `collection`（见 3.1）；
- CLI 快捷创建（只认已登记的笔记本）：
  ```bash
  npx hexo stellar new note --notebook reading-notes --title "标题" --tags "阅读/方法,工具" --dry-run  # 先预览
  ```
- 标签用 `/` 做层级 → 自动生成标签树（`tagtree` Widget 展示在列表/详情页左栏）。

### 4.4 菜单与高亮（active_menu）

- 菜单项需要有真实页面：`url` 指向不存在的页会 404。
- 菜单项 `id`（kebab-case 非空）用于和 `profiles.<类型>.active_menu` 配对 → 当前页面高亮对应菜单。
- Wiki 内容页默认隐藏固定菜单（只留目录树），因此**不要**在 `profiles.wiki` 上设置指向隐藏菜单的 active_menu（本站已验证：会报错）。

## 5. 布局：三栏 Region 与 Widget

### 5.1 三栏与页面类型

- `topbar`（顶）、`leftbar`（左：品牌+主菜单）、`rightbar`（右：目录/资讯）；
- 每种页面类型对应一个 profile（home / blog_index / post / topic / wiki_index / wiki / notebook_index / note_index / note / author / page / settings / error），每类都可覆盖左右栏 widgets、激活菜单等；
- 覆盖语义：省略=继承、数组=整体替换、`[]`=清空、Region `enabled: false`=隐藏整栏。

### 5.2 主题内置 Widget 实例（`node_modules/.../_data/widgets.yml` 事实来源）

| 实例 id | 布局 | 用途 / 主要参数 |
| --- | --- | --- |
| `toc` | toc | 本文目录：list_number、min_depth、max_depth、collapse |
| `recent` | recent | 最近文章/更新：limit、rss |
| `related` | related | 相关内容：Topic=系列文章、Wiki=相关项目 |
| `tree` | tree | Wiki 目录树（高亮当前页），放左/右内容区 |
| `tagtree` | tagtree | Notebook 层级标签树：expand_all / expand_active / show_tagcon |
| `ghrepo` | ghrepo | GitHub 仓库卡（需集合配置 source.repository） |
| `ghissues` / `ghuser` | — | GitHub Issue 时间线 / 用户卡 |
| `author` | author | 作者卡（需 _data/authors.yml） |
| `tagcloud` | tagcloud | 标签云：min_font/max_font/amount/color/show_count |
| `timeline` | timeline | 数据时间线：api/type/user/limit |
| `latest_comment` | timeline | 最新评论（需接评论服务 API） |
| 系统件 | menu/settings/spacer | menu=渲染该栏菜单；settings=外观设置；spacer 仅顶栏弹性占位 |

**放置矩阵（约）：**
- 顶栏：menu / settings / spacer / toc；
- 左右内容区：toc / tree / tagtree / recent / related / ghrepo / ghissues / ghuser / author / tagcloud / timeline / markdown / linklist；
- menu、settings 属于 Leftbar 固定区，不要写进 leftbar.widgets（会被跳过 + Doctor 警告）。

### 5.3 自定义 Widget（站点级组件库）

新建 `source/_data/widgets.yml`，可**覆盖**主题同名实例或**新增**自定义实例，例如：

```yaml
# source/_data/widgets.yml（可选）
welcome:                 # 自定义实例：markdown 卡片
  layout: markdown
  title: 欢迎
  content: |
    **欢迎来到本站。** 更多入口见左栏菜单。
my_links:                # 链接清单
  layout: linklist
  title: 常用入口
  view: list
  items:
    - { title: 官方文档, url: https://xaoxuu.com/wiki/stellar/ }
```

之后在任意 `widgets:` 数组里引用实例 id（如 `rightbar: {widgets: [welcome, recent]}`）。位置放错会被跳过并在 Doctor 报告中提示。

## 6. 标签插件（写作扩展）

完整速查在站内 Wiki [常用标签插件速查](source/wiki/site-handbook/tag-plugins.md) 与 [文章模板/04-Wiki知识库文档模板.md](文章模板/04-Wiki知识库文档模板.md)；要点：

- 语法：参数空格分隔；`键:值` 命名参数；文本参数放最后、最后一个吸收剩余全部词。
- 多行用成对标签 `{% xxx %} … {% endxxx %}`；分组容器用注释分隔：tabs `<!-- tab 标题 -->`、timeline `<!-- node 标题 -->`、grid `<!-- cell -->`。
- 想展示源码而不执行：把示例放进 ``` 围栏代码块。
- 颜色名：red / orange / yellow / green / cyan / blue / purple（部分组件另支持 light / dark / theme / accent）。

常用且本站已验证的写法：

```markdown
{% note color:cyan 标题 单行提示。 %}
{% box color:green 标题 %}多行正文。{% endbox %}
{% folding color:cyan open:false 折叠标题 %}内容。{% endfolding %}
{% mark 高亮词 color:cyan %}
{% hashtag 链接词 /target/ color:blue %}
{% checkbox checked:true color:green 完成项。 %}
{% copy 可复制文本 %}
{% timeline %}…{% endtimeline %}
{% tabs %}…{% endtabs %}
{% grid bg:card w:220px gap:16px %}…{% endgrid %}
```

其他内置标签（image / gallery / video / audio / button / link / quot / poetry / icon / emoji / table / chat / dropdown / swiper 等）见官方 `reference/tags/*`；拿不准先小范围试用再全站铺开。

## 8. 命令与日常工作流

```bash
npm run doctor     # Stellar 校验：环境、配置、集合登记、页面字段、Widget 位置
                   # 有 issues=退出1；仅 warnings 仍算通过
npm run clean      # hexo clean（清理 db.json 与 public/）
npm run build      # hexo generate 产出 public/
npm run server     # 本地预览 http://localhost:4000/
```

Doctor 也支持结构化输出：`npx hexo stellar doctor --format json`（配合 `--silent`）。

**推荐流程（与文章模板配套）：**
1. 选模板 → 复制到正确目录 → 按 `文章模板/00-使用说明.md` 命名；
2. 按模板里的 Front Matter 填空，删掉注释与 `【】` 占位；
3. 需要登记的（Wiki / Topic / Notebook）按 `文章模板/05-内容登记片段速查.md` 粘贴登记；
4. `npm run doctor` → `npm run clean && npm run build` → `npm run server` 人工验收（列表摘要、目录树、上下篇、图片、链接、搜索）。

## 10. 版本与避坑

- 本站安装 Stellar **v2.0.0-alpha.1**；官方文档现为 **2.0.0-rc.2**，npm 上 **latest 仍是 1.x（1.44.0）**。升级主题版本前先看官方迁移指南（migration/v1-to-v2）。
- 1.x 配置与 v2 不通用；v2 内 alpha→rc 主要是新增能力，旧写法基本兼容，但**新增字段**（如 Hero 多种动效、ai_label、vote/rating 等）要按实际版本使用。
- 网上老教程大量是 1.x 写法，`widgets:` 顶层、`wiki:` 字段等都不要再抄。
- 遇到 Doctor/构建报错：先看报错里的 source/path/migration 提示；Widget 放错位置是 warning（exit 0）但仍建议修正。
